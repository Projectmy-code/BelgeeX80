# BELGEE X80 — сайт с модерацией

## Установка
1. Создайте проект в Supabase (https://supabase.com).
2. Откройте SQL Editor и выполните `supabase/schema.sql`.
3. В `js/config.js` укажите Project URL и **publishable/anon** key. Никогда не указывайте service_role/secret key.
4. В Supabase Authentication настройте Site URL и redirect URLs для адреса сайта. Включите подтверждение email (рекомендуется).
5. Опубликуйте папку на HTTPS-хостинге (Netlify, Vercel, обычный хостинг с поддержкой статических файлов). Для локальной проверки запустите `python3 -m http.server 8000` в папке проекта и откройте `http://localhost:8000`.
6. Зарегистрируйтесь через `login.html`. После этого в SQL Editor выполните команду (замените email):
   `update public.profiles set role='admin' where id=(select id from auth.users where email='you@example.com');`
7. Войдите заново и откройте `admin.html`.

## Поведение
- `everyone`: любой гость и зарегистрированный участник отправляет статьи; они получают `pending`.
- `registered`: только вошедшие пользователи отправляют статьи.
- `admin`: отправка пользователями закрыта; администратор управляет существующими материалами.
- Только администратор одобряет, отклоняет и удаляет статьи. Проверки работают в базе через RLS, а не только в интерфейсе.
- На публичной странице видны только `published` статьи из Supabase.

## Важные ограничения перед публичным запуском
- Гостевая отправка в текущем MVP доступна напрямую через Supabase anon API. **До публичного запуска** необходимо добавить CAPTCHA/Turnstile и серверное ограничение частоты отправок через Edge Function, запретив прямую вставку гостями. Иначе возможен спам.
- Гости не могут отслеживать/редактировать свои отправленные статьи. Добавить одноразовые ссылки при необходимости.
- Демонстрационные данные каталога, участников и видео из исходного HTML оставлены без проверки; они не синхронизируются с Supabase.
- В исходном HTML форма обратной связи пока демонстрационная, а видео используют тестовую ссылку. Их необходимо подключить отдельно.
- В режиме `admin` интерфейс подачи закрыт для всех, включая админа: администратор управляет уже существующими материалами из панели.
- Для защиты от XSS статьи отображаются как обычный текст, без интерпретации HTML.
